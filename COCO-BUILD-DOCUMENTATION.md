# COCO-Builds — End-to-End Build System Documentation

## Overview

COCO-Builds is a centralized GitHub Actions CI/CD system for building Android and iOS release binaries from `coco-staging/Coco-patient-mobile` (Expo/React Native app). Workflows run on GitHub-hosted runners, generate native projects via `expo prebuild`, and publish build artifacts as GitHub Releases with tags on the source repo.

## Architecture

```
virajpsimformsolutions/COCO-Builds (this repo)
├── .github/workflows/
│   ├── build-android-apk.yml       ← Patient: APK workflow (dev/testing)
│   ├── build-android-aab.yml       ← Patient: AAB workflow (Play Store)
│   ├── build-android-metro.yml     ← Patient: dev-client APK (Metro backup)
│   ├── build-ios-metro.yml         ← Patient: dev-client iOS (Metro backup, sim or device)
│   ├── tc-build-android-apk.yml    ← TC: APK workflow (dev/testing)
│   ├── tc-build-android-aab.yml    ← TC: AAB workflow (Play Store)
│   ├── tc-build-android-metro.yml  ← TC: dev-client APK (Metro backup)
│   └── tc-build-ios-metro.yml      ← TC: dev-client iOS (Metro backup, sim or device)
└── README.md

coco-staging/Coco-patient-mobile (source repo)
├── app.config.ts                ← Expo config + plugins
├── buildconfig.js               ← ProGuard rules, signing config
├── withCustomSigning.js         ← Expo plugin for Android release signing
├── android/                     ← gitignored, generated by prebuild
├── ios/                         ← gitignored, generated by prebuild
└── .env.development / .env.preview / .env.production
```

## Key Concepts

| Concept | Detail |
|---------|--------|
| **Separate build repo** | Workflows live in `COCO-Builds`, not the source repo — keeps source repo clean |
| **Full Gradle/Xcode on runner** | No EAS Build — full builds run on GitHub Actions runners |
| **expo prebuild** | Generates `android/` and `ios/` directories from Expo config at build time |
| **Post-prebuild patching** | Gradle patches applied after prebuild to fix dependency/compatibility issues |
| **GitHub Releases** | Artifacts published as release assets on `coco-staging/Coco-patient-mobile` with tags |
| **Three environments** | `development`, `preview`, `production` — controlled by workflow input |

## Workflows

### 1. Build Android APK (`build-android-apk.yml`)

**Trigger:** Manual (`workflow_dispatch`)

**Inputs:**
| Input | Default | Options |
|-------|---------|---------|
| `branch` | `develop` | Any branch (e.g., `develop`, `main`, `feat/xyz`) |
| `environment` | `development` | `development`, `preview`, `production` |

**Runner:** `ubuntu-latest` | **Timeout:** 45 minutes

**Pipeline Steps:**

1. **Checkout** — Checks out `COCO-Builds` (this repo) and `coco-patient-mobile` into `app/`
2. **Setup tools** — Java 17 (Temurin), Node.js 20 + Yarn cache
3. **Cache Gradle** — `~/.gradle/caches` + `~/.gradle/wrapper`
4. **Install dependencies** — `yarn install --frozen-lockfile`
5. **Write .env** — From GitHub Secrets → `app/.env`
6. **Decode keystore** — `KEYSTORE_BASE64` → `release.keystore`
7. **Write credentials.json** — For `custom-signing.gradle` to read at build time
8. **expo prebuild** — Generates native Android project with config plugins
9. **Fix DocuSign AAR** — `implementation files()` → `compileOnly files()` in module; removes `flatDir` from root build.gradle
10. **Patch JVM target** — Aligns all subprojects to Java 17
11. **Add stripped DocuSign AAR** — Adds stripped AAR as `implementation` in app build.gradle (Glide classes removed to avoid dex collision with `expo-image`)
12. **Bump JVM metaspace** — `MaxMetaspaceSize=1024m`, heap `4096m`
13. **Build APK** — `./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a -x lint` (arm64 only)
14. **Create tag + Release** — Tag pattern: `build-apk-<env>-<date>-<sha>` → `coco-staging/Coco-patient-mobile`

**Output artifact:** `.apk` file attached to GitHub Release on source repo

---

### 2. Build Android AAB (`build-android-aab.yml`)

**Trigger:** Manual (`workflow_dispatch`)

**Inputs:**
| Input | Default | Options |
|-------|---------|---------|
| `branch` | `develop` | Any branch |
| `environment` | `production` | `development`, `preview`, `production` |

**Runner:** `ubuntu-latest` | **Timeout:** 60 minutes

**Pipeline:** Same as APK except:
- **No `-PreactNativeArchitectures` filter** — All architectures included for Play Store
- **Build command:** `./gradlew bundleRelease --parallel --build-cache -x lint`
- **Output:** `.aab` file
- **Tag pattern:** `build-aab-<env>-<date>-<sha>`

---

### 3. Build iOS IPA (`build-ios-ipa.yml`)

**Trigger:** Manual (`workflow_dispatch`)

**Inputs:**
| Input | Default | Options |
|-------|---------|---------|
| `branch` | `develop` | Any branch |
| `environment` | `production` | `development`, `preview`, `production` |
| `export-method` | `app-store` | `app-store`, `enterprise`, `ad-hoc`, `development` |

**Runner:** `macos-latest` | **Timeout:** 90 minutes

**Pipeline Steps:**

1. **Checkout** — Same as Android (both repos)
2. **Setup tools** — Node.js 20, Ruby 3.3
3. **Install dependencies** — `yarn install --frozen-lockfile`
4. **Write .env** — Same as Android
5. **Import Apple certificate** — `IOS_DIST_CERT_BASE64` + `IOS_DIST_CERT_PASSWORD` → temp keychain
6. **Install provisioning profile** — `IOS_PROVISIONING_PROFILE_BASE64` → `~/Library/MobileDevice/Provisioning Profiles/`
7. **expo prebuild** — Generates native iOS project
8. **pod install** — Installs CocoaPods dependencies
9. **Resolve scheme** — Auto-detects Xcode scheme
10. **Archive** — `xcodebuild archive` with manual signing, Team ID `Z8778PLB65`
11. **Export IPA** — `xcodebuild -exportArchive` with export options plist
12. **Create tag + Release** — Tag pattern: `build-ipa-<env>-<date>-<sha>` → `coco-staging/Coco-patient-mobile`

**Output:** `.ipa` file attached to GitHub Release on source repo

> **Status:** this workflow (and `tc-build-ios-ipa.yml`) existed and worked, but
> was removed from `main` on 2026-07-15 ("fix: ios workflow delete for temp").
> `build-ios-metro.yml` / `tc-build-ios-metro.yml` (below) reuse its proven
> signing/archive/export steps for the `target: device` path, so restoring a
> full App Store IPA workflow later is mostly a matter of copying that logic
> back with `export-method` re-exposed as an input.

---

### 4. Build Android Metro / Dev Client (`build-android-metro.yml`, `tc-build-android-metro.yml`)

**Trigger:** Manual (`workflow_dispatch`)

**Why it exists:** backup path for the free EAS account's build quota/concurrency
limit — produces the same kind of dev-client APK as each source repo's own
`.github/workflows/build-dev.yml` `android-metro-dev` job, but on a full
GitHub-hosted runner instead of EAS Build.

**Inputs:** same as the APK workflow (`branch`, `environment`, default `development`).

**Pipeline:** identical to `build-android-apk.yml` / `tc-build-android-apk.yml`
(same secrets, same DocuSign/JVM/metaspace patches for the patient app), just
retitled and tagged `build-metro-...` / `tc-build-metro-...` so it's clear the
artifact is meant for Metro/dev-client testing rather than QA distribution.

**Output artifact:** `.apk` file attached to GitHub Release on source repo

---

### 5. Build iOS Metro / Dev Client (`build-ios-metro.yml`, `tc-build-ios-metro.yml`)

**Trigger:** Manual (`workflow_dispatch`)

**Why it exists:** same backup rationale as the Android metro workflow above.
The `target: device` path reuses the exact signing/archive/export steps from
the removed `build-ios-ipa.yml` / `tc-build-ios-ipa.yml` (macos-15 + Xcode
16.4 pin included — see the note above about `macos-latest` moving to Xcode
26 and breaking react-native-firebase macro visibility).

**Inputs:**
| Input | Default | Options |
|-------|---------|---------|
| `branch` | `develop` | Any branch |
| `environment` | `development` | `development`, `preview`, `production` |
| `target` | `simulator` | `simulator`, `device` |

**Runner:** `macos-15` (Xcode pinned to 16.4) | **Timeout:** 75 minutes

**Pipeline Steps:**

1. **Checkout** — Both repos
2. **Setup Node.js** + Yarn cache, **Setup Ruby** 3.3, **Select Xcode 16.4**
3. **Cache CocoaPods** — `~/Library/Caches/CocoaPods`, `~/.cocoapods`
4. **Install dependencies** — `yarn install --frozen-lockfile`
5. **Write .env** — Same secrets as the Android workflows for that app
6. **`target: device` only** — import distribution cert into a temp keychain; install provisioning profile(s) (TC installs both the app profile and the `NotifyKitNSE` extension profile, since coco-mobile ships a notification-service-extension target)
7. **expo prebuild** + **pod install** — Generates the native iOS project
8. **TC, `target: device` only** — patches `project.pbxproj` via the `xcodeproj` gem to set manual signing + the correct provisioning profile per target (main app vs. `NotifyKitNSE`), since `xcodebuild` CLI flags can only apply one profile to the whole scheme
9. **Resolve scheme** — `xcodebuild -list`
10. **`target: simulator`** (default, no secrets needed) — `xcodebuild build -sdk iphonesimulator ... CODE_SIGNING_ALLOWED=NO`, zips the resulting `.app`
11. **`target: device`** — `xcodebuild archive` with manual signing (`DEVELOPMENT_TEAM=Z8778PLB65`), then `-exportArchive` with `method: development` to produce a `.ipa`. Fails fast with a clear error if the required secrets aren't set yet.
12. **Create tag + Release** — Tag pattern: `build-ios-metro-<target>-<env>-<date>-<sha>` (`tc-...` for coco-mobile)

**Output:** `.zip` (simulator `.app`) or `.ipa` (device) attached to GitHub Release on source repo

**Additional secrets needed for `target: device`** (not required for `target: simulator`) — same ones the removed IPA workflows used:

| App | Secrets |
|-----|---------|
| Patient | `IOS_DIST_CERT_BASE64`, `IOS_DIST_CERT_PASSWORD`, `IOS_PROVISIONING_PROFILE_BASE64` |
| TC | `COCO_TC_IOS_DIST_CERT_BASE64`, `COCO_TC_IOS_DIST_CERT_PASSWORD`, `COCO_TC_IOS_PROVISIONING_PROFILE_BASE64`, `COCO_TC_IOS_NSE_PROVISIONING_PROFILE_BASE64` |

See "How to prepare iOS secrets" below for how to export these. Until they're
added, run with `target: simulator` — it needs none of them.

## Signing Configuration

### Android

Signing uses `credentials.json` + Expo config plugin:

1. **`withCustomSigning.js`** — Expo config plugin that adds `custom-signing.gradle` to the Android project during prebuild
2. **`credentials.json`** — Generated at build time from secrets, contains keystore path + passwords
3. **`custom-signing.gradle`** — Reads `credentials.json` and configures `signingConfigs.release`

**Keystore details:**
- Alias: `COCOSmileDev`
- Password: `COCOSmile2026`

### iOS

Signing uses manual Xcode code signing:

- Certificate imported to temp keychain on runner
- Provisioning profile installed to `~/Library/MobileDevice/Provisioning Profiles/`
- `CODE_SIGN_STYLE=Manual` + `DEVELOPMENT_TEAM=Z8778PLB65` passed to xcodebuild

## Gradle Patches (Applied Post-Prebuild)

These patches are necessary because:
1. `android/` and `ios/` are **gitignored** — generated fresh each build
2. Some issues are only apparent after prebuild generates the native project

### 1. DocuSign AAR Dependency Fix

**Problem:** `react-native-docusign` bundles a stripped `sdk-pdf` AAR with Glide classes that collide with `expo-image`'s Glide classes at dex merge time. Gradle 9 also forbids local `.aar` deps in library modules during `bundleReleaseAar`.

**Fix:**
- Module `build.gradle`: `implementation files(...)` → `compileOnly files(...)` (not packaged in AAR)
- App `build.gradle`: Add stripped AAR as `implementation files(...)` (available at runtime)
- Root `build.gradle`: Remove `flatDir` (Expo plugin adds it, not needed with `files()`)

### 2. JVM Target Alignment

**Problem:** React Native libraries compile with different Java versions (21, 11, 17), causing `invalid source release` errors.

**Fix:** Appends `gradle.projectsEvaluated` block to root `build.gradle` that forces all subprojects to Java 17.

### 3. JVM Metaspace Bump

**Problem:** Large class metadata from many libraries causes `Metaspace` OOM during dex merge.

**Fix:** `gradle.properties` updated:
- `org.gradle.jvmargs=-Xmx4096m -XX:MaxMetaspaceSize=1024m`

## GitHub Release & Tagging

On successful build, each workflow:

1. Gets the source commit SHA from `app/` (the checked-out source repo)
2. Creates a tag on `coco-staging/Coco-patient-mobile`:
   - Pattern: `build-<type>-<env>-<date>-<sha>` (e.g., `build-apk-development-20260710-a1b2c3d`)
3. Creates a GitHub Release with:
   - Title: `APK development 2026-07-10` (or AAB/IPA)
   - Notes: Branch, environment, commit SHA
   - Asset: The build file (`.apk`, `.aab`, or `.ipa`)

No files are stored as Actions artifacts — everything goes to GitHub Releases.

## Build Speed Optimizations

| Optimization | Impact |
|--------------|--------|
| Gradle cache (`~/.gradle/caches`) | ~30-50% faster on subsequent builds |
| `-PreactNativeArchitectures=arm64-v8a` (APK only) | ~50% faster — single arch vs. 3 |
| `--parallel --build-cache` | Parallel task execution + build cache |
| `-x lint` | Skips lint checks (~10-15% faster) |
| `yarn install --frozen-lockfile` | Deterministic + cached |
| Yarn cache in Node setup | Reuses packages across runs |

## Troubleshooting

### Build fails with "invalid source release: 21"
→ Java 17 target mismatch. The JVM alignment patch should fix this. Check the patch step output.

### "Could not resolve all dependencies for configuration ':react-native-docusign:releaseRuntimeClasspath'"
→ DocuSign AAR dependency issue. Ensure the sed patch runs and the stripped AAR is added to app build.gradle.

### "OutOfMemoryError: Metaspace"
→ Increase `MaxMetaspaceSize` in `gradle.properties`. Current: 1024m.

### iOS signing fails
→ Check `IOS_DIST_CERT_BASE64`, `IOS_DIST_CERT_PASSWORD`, and `IOS_PROVISIONING_PROFILE_BASE64` secrets. Ensure the P12 was exported without issues (OpenSSL 3.x requires `-legacy` flag).

### Release creation fails
→ Ensure `COCO_PAT` has `repo` scope and write access to `coco-staging/Coco-patient-mobile`.
